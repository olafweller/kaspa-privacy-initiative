# Second pass — one frozen six-receipt experiment

- Statement substitution: the immutable image, public package, producer/verifier,
  guest, Join control, all six inputs and complete journals remain those reviewed
  in PR57. B checks package hashes and native contexts before rental; the actual
  Pod configuration and idle service scope are read back before the one start.
  GPU-returned metadata cannot set independent verification expectations.
- Inflation, unauthorized exits and stale backing: the relation/policies are not
  changed. CPU verification and actual native script execution must bind both
  exit receipts to the fixed issued transaction IDs and subsequent signed payout
  IDs. The last drain must clear principal/liabilities without touching state
  rent. Negative controls must be semantic rejections, not process failures.
- Double spends and replay: the reviewed whole-history 22-distinct-input corpus
  remains frozen. Receipt journal mutations, wrong program/control and corrupted
  seals are rejected by cryptographic verification. Native script acceptance in
  synthetic context is not a fresh consensus/UTXO/replay qualification on TN10.
- Untrusted archive: the separately corrected B client bounds compressed bytes
  and full gzip expansion before tar parsing. Hash/size, regular-file, canonical
  paths and duplicate constraints remain. Only trusted package executables run;
  downloaded input/assets are checked against independent pins.
- Partial/failure handling: candidate receipts survive later failure. Full success
  requires six final receipts, both native paths, all per-batch matching-process
  CUDA evidence and operational preservation/cleanup. The one process-group
  timer covers every proof/compression/check without a per-batch reset; no retry
  or extension is authorized. Remote mutation uncertainty is reconciled read-only.
- Dependency disappearance: the B guard owns the provider deadline/backup/stop;
  Cloud, TN10 gateway and laptop are not runtime dependencies. Stop confirmation
  and deletion remain distinct. Deletion requires B archive revalidation and an
  independently verified Cloud copy; a compute stop alone leaves volume charges.
- Keys/privacy: B root remains a trusted administrator. Existing credentials are
  loaded only on B; account keys never enter Cloud or GPU processes. Public
  fixtures do not demonstrate independent wallet custody, hidden network or
  amount metadata, or production financial privacy. No wallet files are read.
- Chain/upgrade boundary: no new funding or broadcast, no alteration of the old
  PR54 instance, and no migration/admin withdrawal path. These receipts certify
  synthetic frozen anchors. A real new TN10 instance and independently available
  current state/history require separately released live execution and new proofs.

The retained evidence checker repeats real CPU receipt/native verification and
recomputes CUDA activity from raw process samples. It makes no provider request,
starts no proof and does not infer live chain acceptance from local results.
