# Architecture Decision Records

Architecture Decision Records (ADRs) document important technical choices so the project does not depend on memory, personality, or social authority.

## File naming

```text
0001-state-architecture.md
0002-note-model.md
0003-proof-system.md
0004-exit-model.md
...
```

## Status values

- Proposed
- Accepted
- Superseded
- Rejected
- Experimental

## Rules

An ADR should:

- state the problem;
- list constraints;
- compare credible alternatives;
- identify security/privacy implications;
- cite evidence;
- record objections;
- explain why the decision was made;
- state what evidence would cause reconsideration.

Use [0000-template.md](0000-template.md).
